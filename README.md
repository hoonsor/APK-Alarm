# 鬧鐘（HoonsorAlarm）

一個以「絕對不能漏響」為第一優先的 Android 鬧鐘 App，整合鬧鐘、倒數計時、碼錶與語音建立。

## 這個 App 能幫你做什麼

- **一眼看完所有鬧鐘**：兩欄網格，一屏約 10 個；每格顯示時間、重複星期、提醒文字與開關。
- **快速編輯**：點卡片從底部滑出編輯面板，七個星期鈕直接切換，或用「平日」「週末」切換鈕快速加入（兩顆都按＝每天）；提醒文字直接修改。
- **群組**：鬧鐘與計時器都可分組，每個群組自動配上不同底色（可自行更改），群組可展開／收合；群組總開關可整組暫停（例如放假），重新打開時每個鬧鐘恢復原本的開關狀態。
- **略過下次**：點進鬧鐘或長按多選後按「略過下次」，只跳過下一次響鈴（例如平日鬧鐘週一響過後略過，週二不響、週三照常），卡片會以洋紅色外框與「略過下次」標籤標示，可隨時取消（只響一次的鬧鐘不能略過）。
- **複製與批次操作**：面板內一鍵複製；長按卡片進入選取模式，可批次複製、移到群組、啟用／停用、刪除（刪除後 10 秒內可復原）；再長按已選卡片，卡片會收合成一疊，直接拖曳到群組。
- **響鈴畫面**：可為每個鬧鐘或全域設定一張照片，滿版顯示並加上橢圓／方形暗角，強度可調；提醒文字以大字顯示。音量 30 秒漸強，走鬧鐘音量通道，勿擾模式照常響。
- **語音念出提醒**：鬧鐘可改成用人聲念出提醒文字（可先念時間）取代鈴聲。可設定「念一次後改播鈴聲」，避免一直重複念。可用手機內建語音（免費、離線），或 MiniMax 雲端語音；雲端語音在儲存時就預先產生並存在手機，響鈴當下不需要網路，失敗時自動改用內建語音或鈴聲。語音一律以鬧鐘全音量播放，嫌小聲可在設定頁「語音增幅」再加大（最多 +15 dB）。
- **一次性鬧鐘與計時器**：只響一次的鬧鐘可在編輯面板打開「一次性」，計時器在新增或編輯時打開「一次性」，響完（按停止或響太久自動停止）就自動刪除，不會越積越多；貪睡時不刪。卡片上標示「一次性」。語音總控新增的鬧鐘與計時器預設就是一次性，說「固定」「重複」「常駐」「保留」才會留下來。
- **個別音量與震動**：每個鬧鐘可指定音量與是否震動，響鈴結束後自動還原手機音量；也可設成「僅震動」的純震動鬧鐘，不出聲也不會打斷音樂。
- **自訂鈴聲**：鬧鐘、計時器各有預設鈴聲，每個鬧鐘也可另外指定；可選系統鈴聲或匯入自己的 mp3。音檔會複製到 App 內，原檔刪除也不影響；無法播放時自動改用系統鈴聲。
- **倒數計時與碼錶**：多個計時器同時進行，可用上下滑動的時／分／秒滾輪或數字鍵盤設定時長，並即時顯示幾點會響；點卡片可修改剩下的時間（滾輪、+1／+5／+10／+30 分／+1 時、−1／−5／−10／−30 分／−1 時，「重設」仍回到最初的時長），響完自動回到原本的時長；計時器以兩欄卡片顯示，開始倒數後標示幾點會響（時:分），可依剩餘時間或建立時間排序、長按多選批次分組、暫停、繼續、全部重設或刪除，也可分群組，群組開關一次暫停或繼續整組；碼錶支援分段並標示最快／最慢。兩者在 App 被關閉或鎖屏時都持續運作。
- **語音建立**：說「每週一三五早上七點十五叫我晨跑」「二十五分鐘後提醒我起來走動」「把晨跑那個改成六點半」「新增鬧鐘群組叫上班，平日七點叫我出門」「關閉上班群組」即可建立或修改鬧鐘、計時器與群組；時間有歧義（例如凌晨說「明天早上」）會讓你選。
- **AI 解析（MiniMax M3）**：在設定頁填入 API key 後，語音內容交給 MiniMax M3 理解，key 以手機 Keystore 加密保存。AI 只負責「提出」動作，一律經你確認才寫入，排程仍在手機本地執行；沒網路或 AI 失敗時自動改用離線解析。
- **立即測試**：每個鬧鐘可按「測試」用實際設定試響；可靠度頁也能立即測試鈴聲與語音播報。
- **響鈴可靠度檢查**：檢查精準鬧鐘、全螢幕響鈴、通知、電池最佳化、鬧鐘音量，並比對「App 預期」與「系統實際登記」的下一次響鈴。
- **語音總控（Hoonsor Agent API）**：安裝同一把簽章的「語音總控」後，可以用說的查詢、新增、修改、開關、略過、刪除鬧鐘，開關群組，開始、暫停、繼續、重設、刪除計時器。動作清單見 [docs/AGENT_API.md](docs/AGENT_API.md)，例句見語音總控的使用說明書。設定頁有「API 測試台」，可靠度頁會顯示語音總控是否安裝與簽章是否相同。
- **支援標準 Intent**：Google 助理或你自己的自動化工具可用 `ACTION_SET_ALARM`、`ACTION_SET_TIMER` 直接在本 App 建立鬧鐘與計時器。

- **備份與還原**：鬧鐘、群組、計時器與設定可打包成一個備份檔（可選擇是否包含圖片與鈴聲）。可以「分享」給 LINE、新增至 Dropbox、上傳到雲端硬碟等任何 App，或「儲存到檔案」；匯入可選「合併」或「取代」。手機開啟 Google 備份時，Android 也會自動備份並在重新安裝或換手機時還原。
- **免接線更新**：每天開啟時自動檢查 GitHub 上的新版，也可在設定頁按「檢查更新」；確認後直接下載並交給系統安裝，鬧鐘資料保留、更新完自動重新排程。也支援用 Obtainium 追蹤更新。

## 為什麼比一般鬧鐘可靠

1. 所有提醒（含計時器）都用系統優先權最高的 `setAlarmClock()` 排程。
2. 每個提醒另外排一個 60 秒後的備援；主排程已觸發就忽略備援，沒觸發就補響。
3. 資料庫是唯一資料來源：開機、改時間、換時區、App 更新、權限變更、每次開啟 App，都會**全量重新排程**，不依賴「響完再排下一次」。
4. 響鈴由前景服務負責，10 分鐘無人處理會留下「已錯過」通知。

## 建置與安裝

需求：Android Studio（Ladybug 以上）、JDK 17、Android 8.0（API 26）以上的手機。

1. 用 Android Studio 開啟本資料夾，等待 Gradle Sync 完成（首次會下載 Gradle 8.11.1 與相依套件）。
2. 手機開啟 USB 偵錯並連接電腦，按 **Run ▶** 安裝。
3. 首次開啟：允許通知權限，然後點右上角狀態燈進入「響鈴可靠度」，把橘色項目逐一處理（尤其是電池最佳化豁免與廠牌自啟動）。
4. 在可靠度頁按「測試響鈴：1 分鐘後」，鎖屏等待確認響鈴畫面正常。

單元測試：`./gradlew test`（涵蓋下次響鈴計算、語音解析與版本比較）。

## 手機端更新（不用接線）

正式版由 GitHub Actions 編譯、用共用金鑰 `hoonsor-release.jks` 簽章，發布在 [Releases](https://github.com/hoonsor/APK-Alarm/releases)。手機有兩種更新方式，擇一或並用：

**App 內更新（建議）**
- 每天第一次開啟 App 時在背景檢查一次；有新版會跳出版本號與更新說明，可選「下載並更新」「稍後」或「略過此版」。
- 設定頁最下方「App 更新」可隨時手動檢查。
- 第一次更新時會引導你到「安裝不明應用程式」允許本 App，回到 App 後自動開始下載。
- 沒網路或 GitHub 無法連線時安靜略過，不影響任何鬧鐘。

**Obtainium 設定**
1. 在手機安裝 [Obtainium](https://github.com/ImranR98/Obtainium/releases)。
2. 「Add App」→ App Source URL 填 `https://github.com/hoonsor/APK-Alarm`。
3. 保持「Include prereleases」關閉（`latest` 是每次推送 main 自動編譯的測試版，不要追它）。
4. 若同一個 Release 未來有多個 APK，在「Filter APKs by Regular Expression」填 `HoonsorAlarm-v.*\.apk`。
5. 新增後 Obtainium 會定期檢查，有新版時通知並一鍵安裝。

**第一次切換到正式簽章版（只需一次）**：如果手機上現在是用 Android Studio 直接安裝的 debug 版，簽章不同，系統不允許覆蓋安裝。請先在設定頁「備份與還原」分享備份檔 → 解除安裝 → 從 Releases 安裝正式版 → 匯入備份（選「取代」）。之後就都能直接更新。

## 如何發新版

1. 修改 `app/build.gradle.kts` 的 `versionCode`（加 1）與 `versionName`（例如 `0.11.1`）。
2. 在 `PROJECT_STATUS.md` 新增 `### v0.11.1 — 日期` 段落，這段文字會自動成為 Release 的更新說明（也就是 App 內更新對話框顯示的內容）。
3. 提交並推送 main，接著推送同名 tag：

   ```bash
   git tag v0.11.1
   git push origin main v0.11.1
   ```

4. GitHub Actions 會跑單元測試、編譯 `HoonsorAlarm-v0.11.1.apk` 並建立正式 Release。tag 與 `versionName` 不一致時 CI 會直接失敗，避免 App 一直以為有新版。

其他說明：
- 每次推送 main 都會更新名為 `latest` 的預先發行版（`HoonsorAlarm-latest.apk`），給想搶先測試時手動下載；App 內更新與 Obtainium 預設都不會把它當成新版。
- 簽章 Secrets（`SIGNING_KEYSTORE_B64`、`SIGNING_STORE_PASSWORD`、`SIGNING_KEY_ALIAS`、`SIGNING_KEY_PASSWORD`）由倬執行 `setup-hoonsor-signing.ps1` 寫入。沒有 Secrets 時 CI 會用 debug 簽章並顯示警告，這種 APK 無法覆蓋安裝，不要拿來發正式版。

## 專案結構

```
app/src/main/java/com/hoonsor/alarm/
├── AlarmApp.kt            Application 與 Graph（服務定位）
├── data/                  Room 實體、DAO、設定、Repository（所有寫入的入口）
├── domain/Schedule.kt     下次響鈴計算、星期、格式化
├── scheduler/             AlarmScheduler（可靠度核心）、Receiver
├── ringing/               響鈴前景服務、通知、響鈴畫面（圖片＋暗角）
├── image/ImageStore.kt    響鈴圖片匯入（複製壓縮到 App 內部）
├── sound/SoundStore.kt    鈴聲匯入、名稱、試聽
├── agent/                 Hoonsor Agent API（語音總控用的 describe／execute／health）
├── backup/                備份檔匯出、匯入（合併／取代）
├── update/                App 內自我更新（查 GitHub Releases、下載、PackageInstaller 安裝），可整包複製到其他 APP
├── tts/TtsEngine.kt       語音播報（念出文字、MiniMax 預先產生與快取）
├── voice/                 語音辨識畫面、AI 解析（AiParser）與離線規則解析
└── ui/                    鬧鐘、計時器、碼錶、可靠度、設定畫面
```
